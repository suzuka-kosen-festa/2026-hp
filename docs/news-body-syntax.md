# お知らせ（news）の書き方

`site/src/data/news.json` を編集するだけでお知らせを追加できる。コードは触らない。

> この内容はもともと `news.json` の中に `article2`「この仕組みについて」というお知らせとして入っていたが、
> 中身は編集者向けの説明でありサイト訪問者に見せるものではないため、ここへ移した。

## 1件の形

```json
{
  "id": "一意のスラッグ",
  "date": "2026.09.20",
  "title": "お知らせのタイトル",
  "href": "リンク先（任意）",
  "body": "本文（任意）"
}
```

| キー | 必須 | 説明 |
|---|---|---|
| `id` | ○ | URLになるので半角英数とハイフンで。`/news/<id>/` |
| `date` | ○ | `2026.09.20` の形式。`.` `-` `/` のどれでも読める |
| `title` | ○ | 一覧に出る見出し |
| `href` | | リンク先。`/booth/` のような内部ページや外部URL |
| `body` | | 本文。**書くと `/news/<id>/` の記事ページが自動で作られる** |

## リンクの決まり方

1. `href` があればそこへ飛ぶ
2. `href` が無く `body` があれば `/news/<id>/`（自動生成された記事ページ）
3. どちらも無ければ**リンクにならない**（押せない項目になる）

**`href` は `body` より強い。** 両方書くと記事ページは作られるのに一覧からは `href` の先へ飛ぶので、記事が読めなくなる。どちらか一方にすること。

基本は既存ページへのリンク（出店一覧の公開 → `/booth/`）で、単体で読ませたい内容があるときだけ `body` を書く。

## 日付のふるまい

- **未来の日付を書いたお知らせは表示されない。** 書きかけの告知をコミットしても、日付が来るまで出ない
- ただし**予約投稿ではない**。サイトは push のたびにビルドして配るので、日付が来ても誰も push しなければ出ない。公開日に合わせて出したいなら、その日にリリースPRを出す
- 公開から**7日以内**は自動で `NEW` バッジが付く（日数は `site/src/lib/news.ts` の `NEW_THRESHOLD_DAYS`）

## body で使える記法

行の先頭に記号を置く。**1行に1つだけ**で、組み合わせはできない。

| 書き方 | 表示 |
|---|---|
| `# 見出し` | 大見出し |
| `## 見出し` | 中見出し |
| `### 見出し` | 小見出し |
| `#### 見出し` | さらに小さい見出し |
| `- 項目` | 行頭に「・」が付く箇条書き |
| `* 文章` | 太字の段落 |
| `> 文章` | 引用（画鋲付きのカードで表示される） |
| 記号なし | ふつうの段落 |
| `\n` | 改行 |

### 注意

- **記号のあとに半角スペースが要る。** `#見出し` は効かず、そのまま文字として出る
- `\n` の直後に記号を置くときも同じで、`\n # タイトル` のように余計な空白を入れると効かない
- **本文中にリンクは書けない。** リンクを踏ませたいお知らせは `body` ではなく `href` を使う
- JSONの文字列なので、改行は実際の改行ではなく `\n` と書く

### 例

```json
{
  "id": "site-open",
  "date": "2026.09.20",
  "title": "公式サイトを公開しました",
  "body": "# 公式サイトを公開しました\n\n本文をここに書く。\n\n## 小見出し\n\n- 箇条書き1\n- 箇条書き2"
}
```
